AdSense: code is not approval

Your goal is to monetize the existing Vocabulary Deck Generator. The first win is knowing where the ad code goes—and what must happen before it can earn anything.

Three separate steps

  1. Submit: In AdSense, add your public domain under Sites.
  2. Verify: Google gives you a publisher-specific script. Place it in the shared page <head>, then request review.
  3. Serve: After the site is approved, enable Auto ads or add ad units. A script alone does not mean ads will appear or earn revenue.

Where it fits in this project

The app’s shared HTML shell is web/index.html. Its <head> currently has metadata and a title. Since this shell serves the frontend, that is where Google’s actual script would go—only after you register the live domain and receive your code.

<head>
  ...
  <script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-YOUR_ID"
    crossorigin="anonymous"></script>
</head>

YOUR_ID is a placeholder, not valid code. Copy the exact snippet from your AdSense account; don’t paste it yet.

Before asking Google to review

  • Make the site publicly reachable over HTTPS.
  • Publish a privacy policy that explains advertising cookies and data use.
  • Make sure Google can review useful, complete content. A login-only utility may not present enough publicly accessible content.
  • Protect the Gemini API from unexpected public usage; AdSense approval does not pay those bills automatically.
